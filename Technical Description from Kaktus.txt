Техническое задание: Сайт-афиша «чтоунастамзавтра.рф»

Версия: 3.0 (полная, с учётом всех дополнений)
Дата: 18 августа 2026 г.

---

1. ВВОДНАЯ ЧАСТЬ

1.1. Название проекта

Сайт-афиша «чтоунастамзавтра.рф» – умная городская афиша с нейросетевыми функциями и интеграцией с проектом «фоткибудутзавтра.рф».

1.2. Цель проекта

Создать единую платформу для поиска, анонсирования и продвижения мероприятий в Новокузнецке и Кемеровской области. Платформа должна стать центральным звеном экосистемы, объединяющей афишу, продажу репортажных фотографий («фоткибудутзавтра.рф») и автоматическую генерацию контента через нейросети.

1.3. Задачи проекта

· Обеспечить удобный поиск и фильтрацию событий для конечных пользователей.
· Предоставить организаторам инструменты для самостоятельного добавления и управления событиями.
· Внедрить систему модерации для контроля качества контента.
· Интегрировать платёжную систему для монетизации премиум-функций.
· Обеспечить юридическую чистоту (маркировка рекламы, обработка персональных данных, онлайн-касса).
· Создать единый визуальный стиль с проектом «фоткибудутзавтра.рф».
· Реализовать вход через популярные российские сервисы (VK, MAX, Яндекс).
· Предоставить удобный календарь событий и умный поиск с фильтрацией.

1.4. Целевая аудитория

· Посетители: жители Новокузнецка и Кемеровской области в возрасте 18–45 лет, ищущие досуг.
· Организаторы: ивент-агентства, клубы, рестораны, спортивные клубы, частные лица.
· Администратор/Модератор: владелец проекта или назначенное лицо.

2. СТРУКТУРА САЙТА

2.1. Публичная часть (для всех пользователей)

· Главная страница – лента событий, блок «Скоро начнётся», фильтры, календарь (сокращённый вид).
· Страница события – полная карточка с описанием, картой, фото, кнопками действий.
· Страница календаря – полноэкранный календарь на месяц/неделю с кликабельными датами и списком событий.
· Страница поиска – расширенный поиск с фильтрами по тексту, категории, дате, цене, району.
· Страницы «О проекте», «Договор-оферта», «Политика конфиденциальности».

2.2. Личный кабинет пользователя (посетитель)

· Избранные события, история просмотров, настройка уведомлений.

2.3. Личный кабинет организатора

· Список событий со статусами, форма добавления, статистика, управление тарифом, история платежей.

2.4. Админ-панель (модератор/администратор)

· Дашборд со статистикой, модерация событий, управление организаторами, обработка жалоб, настройки (чёрный список слов, тарифы, интеграции).

3. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

3.1. Роли пользователей и права доступа

· Посетитель: просмотр, фильтры, избранное, жалобы, регистрация.
· Организатор: всё, что у посетителя + управление событиями, оплата тарифов, статистика.
· Модератор: просмотр публичной части + модерация событий, жалоб, управление организаторами (без удаления аккаунтов).
· Администратор: полный доступ, включая управление пользователями, тарифами, настройками.

3.2. Регистрация и авторизация (расширенная)

3.2.1. Способы входа

· Email + пароль – стандартная регистрация с подтверждением (две галочки: оферта и согласие на ПД).
· VK ID – OAuth 2.0 через VK API.
· MAX ID – OAuth 2.0 (при наличии API).
· Яндекс ID – OAuth 2.0 через Яндекс OAuth (используется Yandex.Passport API для получения email и имени).

3.2.2. Технические детали (Яндекс ID)

· Регистрация приложения на https://oauth.yandex.ru/client/new, указание Redirect URI: https://чтоунастамзавтра.рф/auth/yandex/callback.
· Использовать поток Authorization Code Flow с обменом code на access_token через https://oauth.yandex.ru/token.
· Получение данных пользователя через https://login.yandex.ru/info?format=json.
· Для FastAPI рекомендуется использовать библиотеку fastapi-sso или реализовать самостоятельно с httpx.
· При первом входе через Яндекс создаётся локальный аккаунт (связка по уникальному ID Яндекса).
· Пользователь даёт согласие на обработку ПД отдельным чекбоксом при первом входе.

3.2.3. Обязательные поля для организатора

· Название организации/ИП, ИНН, контактный телефон, юридический/фактический адрес.
· Первая заявка на статус организатора проходит ручную верификацию (проверка ИНН через ФНС).

3.2.4. Безопасность

· Хеширование паролей bcrypt, JWT-токены для сессий, refresh_token для продления сессии.

3.3. Календарь событий (новый раздел)

· Отображение: календарь на месяц с выделением дат, на которые есть события.
· Навигация: кнопки «Назад» / «Вперёд» для переключения месяцев.
· Интерактивность: клик по дате открывает список событий на этот день (под календарём или в модальном окне).
· Фильтрация: возможность отфильтровать события по категориям прямо в календаре.
· Адаптивность: корректно отображается на мобильных устройствах.
· Интеграция с бэкендом: календарь загружает события через API с параметрами start_date и end_date.
· Рекомендуемая библиотека: EventCalendar (@event-calendar/core) – MIT, 35KB, zero-dependency.

3.4. Умный поиск и фильтрация (новый раздел)

· Поиск по тексту: по названию, описанию, месту, организатору.
· Фильтры: категория, диапазон дат (от – до), цена (бесплатные / платные / диапазон), район города.
· Сортировка: по дате, популярности, цене (возможность выбора).
· Real-time поиск: с debounce (задержка 300 мс) для обновления списка при вводе.
· Расширенные фильтры: выдвижная панель или отдельная страница /search.
· Техническая реализация: эндпоинт GET /api/events?search=...&category=...&date_from=...&date_to=...&price_min=...&price_max=...&sort=....
· Для ускорения: индексы в PostgreSQL на поля title, location, category, date. Полнотекстовый поиск через pg_trgm или tsvector при росте базы.

3.5. Модерация и безопасность

· Верификация организатора: первая заявка – ручная проверка ИНН и данных.
· Модерация событий: первые 3 события от организатора – премодерация, затем автоматическая публикация с возможностью пост-модерации.
· Автоматические фильтры: капча (Яндекс.Капча / hCaptcha) при отправке формы; проверка чёрного списка слов.
· Жалобы: кнопка «Пожаловаться» на карточке события. При 5+ жалобах – автоматическое скрытие и отправка на проверку администратору.
· Репутация: оценка организатора после события (1–5 звёзд), низкий рейтинг (<3) → премодерация всех новых событий.

3.6. Тарифы и монетизация

· Бесплатный тариф: публикация бесплатных событий, без нейрогенерации, без автопостинга.
· Премиум (платный): разовая публикация (500–1000 ₽) или подписка (5000 ₽/мес). Премиум-функции: указание цены билета, продажа билетов (комиссия 5–10%), генерация постера и описания нейросетью, автопостинг в VK/MAX, закрепление в топе на 3 дня.

3.7. Платёжная система

· Интеграция с ЮKassa (или CloudPayments).
· Поддержка разовых и рекуррентных платежей.
· Обязательная выдача электронных чеков (онлайн-касса по 54-ФЗ).

3.8. Нейросетевые функции

· Генерация постера: по названию и категории (Stable Diffusion) – доступно для платных тарифов.
· Генерация описания: через Yandex GPT / ruGPT – доступно для платных тарифов.
· Рекомендации: умная лента на основе истории просмотров и избранного.

3.9. Интеграции (российские)

· «фоткибудутзавтра.рф» – подгрузка фото на карточку события (по ID фотосессии).
· VK – авторизация (VK ID), автопостинг.
· MAX – авторизация (MAX ID), уведомления.
· Яндекс – авторизация (Яндекс ID).
· Яндекс.Карты – отображение места.
· ЮKassa / CloudPayments – приём платежей.
· Яндекс.Капча – защита от ботов.
· (Опционально) Яндекс.Метрика – аналитика.

4. ДИЗАЙН И ИНТЕРФЕЙС

· Стиль: «Фотографический минимализм», продолжение бренда «фоткибудутзавтра».
· Цвета: #F8F9FA (фон), #0B1A33 (основной тёмный), #0099FF (акцентный). Карточки – белые с мягкой тенью.
· Шрифты: Montserrat (заголовки), Open Sans (текст).
· Адаптивность: Mobile First (три состояния: 375px, 768px, 1280px).
· Карточка события: постер 60–70% карточки, заголовок, метаданные, цена, иконка «сердце», плашка «Реклама» для платных.
· Календарь: отдельная страница /calendar, интеграция с лентой событий (при клике на дату – подгрузка событий).
· Поиск: строка в шапке, выпадающие фильтры, кнопка «Расширенный поиск».

5. ТЕХНИЧЕСКАЯ АРХИТЕКТУРА
· Бэкенд: Python 3.11, FastAPI, SQLAlchemy, PostgreSQL (в продакшене), SQLite (для разработки).
· Аутентификация: JWT + OAuth2 (VK, MAX, Яндекс).
· Фоновые задачи: Celery + Redis (генерация постеров, отправка уведомлений).
· Фронтенд: React / Next.js (или Vue.js), TailwindCSS, React Router, Axios, Яндекс.Карты API.
· Инфраструктура: хостинг – российский VDS (Рег.облако, TimeWeb, Beget), репозиторий – GitVerse, облачное хранилище – Яндекс.Диск / Облако Mail.ru, документы – Кайтен / МойОфис, мессенджер – MAX / VK.

6. ЮРИДИЧЕСКИЕ ТРЕБОВАНИЯ (РФ, 2026)

· Маркировка рекламы: все платные размещения – пометка «Реклама», указание рекламодателя, ERID (получение через ОРД, интеграция с ЕРИР).
· Договор-оферта: отдельная страница, акцепт при регистрации или оплате.
· Обработка ПД: регистрация оператора в Роскомнадзоре, политика конфиденциальности, отдельный чекбокс согласия.
· Онлайн-касса: обязательная интеграция с облачной кассой для выдачи чеков.
